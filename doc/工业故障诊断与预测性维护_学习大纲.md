# 工业故障诊断与预测性维护（PHM）学习大纲
### 面向数据/算法背景，目标：独立完成"IoT传感器数据 → 故障诊断 → 风险预测"全流程

---

## 课程目标

学完本大纲后，你应该能够独立完成以下能力：

1. 拿到一份工业传感器时序数据（振动、温度、电流等），能做完整的探索性分析
2. 会提取时域、频域、时频域特征，理解每个特征背后的物理意义
3. 能搭建异常检测系统（无监督），在没有故障标签的情况下发现异常
4. 能搭建故障分类系统（有监督），识别具体故障类型
5. 能搭建剩余寿命预测（RUL）模型，预测设备还能安全运行多久
6. 理解一个完整的PHM系统架构，能把模型集成到实际的监控/报警系统里

**预计学习周期**：如果每天投入1.5-2小时，大约需要**12-16周**。可以根据你的基础调整节奏，但不建议跳过动手项目，PHM是一个"做出来才算会"的领域。

## 阶段一：工业设备与失效机理基础（1周）

### 为什么这一步不能跳过
很多人直接冲进算法，结果做出来的模型"技术上正确，但没有物理意义"。比如你提取了100个特征喂给模型，但根本不知道轴承内圈故障对应哪个频率，这样出了问题你无法排查，也无法向工程师解释你的结果。

### 学习内容

1. **常见旋转设备结构**
   - 滚动轴承（Rolling Element Bearing）：内圈、外圈、滚动体、保持架
   - 齿轮箱：齿轮啮合、传动比
   - 电机：定子、转子、绕组
   - 泵/压缩机：叶轮、密封、气蚀

2. **常见失效模式（Failure Mode）**
   - 轴承：点蚀、剥落、磨损
   - 齿轮：断齿、点蚀、磨损
   - 电机：轴承故障、绕组绝缘老化、转子断条、气隙偏心
   - 不平衡（Unbalance）、不对中（Misalignment）、机械松动（Looseness）

3. **失效频率的物理含义**
   - 轴承特征频率：BPFO（外圈故障频率）、BPFI（内圈故障频率）、BSF（滚动体故障频率）、FTF（保持架频率）
   - 齿轮啮合频率（GMF, Gear Mesh Frequency）
   - 这些频率如何根据设备几何参数和转速计算出来

4. **FMEA（失效模式与影响分析）思维方式**
   - 了解工程师是如何系统性梳理"什么部件、会以什么方式坏、坏了有什么后果"的

### 推荐资源
- SKF/NSK等轴承厂商官网的技术白皮书（免费，讲得很清楚）
- 搜索关键词："bearing fault frequency calculation"、"rotating machinery fault diagnosis basics"
- 书籍：《旋转机械故障诊断技术》（中文，工程向，可选读部分章节）

### 自测标准
给你一个轴承型号和转速，你能查公式算出BPFO/BPFI大概是多少Hz。

## 阶段二：IoT传感器与数据采集知识（1周）

### 学习内容

1. **常见传感器类型及其物理量**
   - 加速度传感器（振动）：压电式、MEMS式，测的是加速度，可积分得到速度/位移
   - 温度传感器：热电偶、热电阻（PT100）、红外测温
   - 电流/电压传感器：用于电机健康监测（电流特征分析法 MCSA）
   - 声发射传感器：捕捉高频应力波，用于早期裂纹检测
   - 油液监测：金属颗粒计数、粘度、水分含量

2. **采集参数的意义（这部分很多算法背景的人会忽略，但非常关键）**
   - 采样率（Sampling Rate）：奈奎斯特采样定理，采样率至少是关注频率的2倍以上，实际工程里一般取5-10倍
   - 采样时长/采样点数：影响频率分辨率
   - 抗混叠滤波：为什么采集前要先滤波

3. **数据传输与存储架构（了解即可，不用精通）**
   - 边缘计算 vs 云端计算：哪些计算适合在设备端做，哪些适合传到云端
   - 通信协议：MQTT（轻量级，IoT常用）、OPC-UA（工业标准）、Modbus（老旧设备常用）
   - 时序数据库：InfluxDB、TimescaleDB，为什么普通关系型数据库不适合存高频传感器数据

### 推荐资源
- 搜索："MQTT protocol tutorial"、"nyquist sampling theorem explained"
- InfluxDB官方入门文档

### 自测标准
给你一个设备最高关注频率（比如3kHz的轴承故障频率），你能说出合理的采样率应该设多少，并解释为什么。

## 阶段三：信号处理核心技术（3-4周，本课程重点之一）

这是整个PHM里技术含量最高、最容易被算法背景的人低估的部分。很多人直接把原始信号扔进神经网络，效果往往不如先做好信号处理再上传统机器学习。

### 3.1 时域分析（3-4天）

**学习内容**：
- 基础统计量：均值、标准差、方差
- 峰值（Peak）、峰峰值（Peak-to-Peak）
- **均方根值 RMS**：反映信号能量水平，常用于监测整体振动强度趋势
- **峭度 Kurtosis**：对冲击信号（如轴承早期点蚀产生的冲击）非常敏感，是早期故障检测的重要指标
- **峰值因子 Crest Factor**（峰值/RMS）、**裕度因子 Clearance Factor**、**波形因子 Shape Factor**
- 这些指标各自对什么类型的故障敏感（比如峭度对早期局部损伤敏感，RMS对整体劣化敏感）

**动手项目**：
用CWRU轴承数据集（见阶段五资源清单），对正常/故障信号分别计算上述所有时域特征，画出对比图，观察哪些特征在故障状态下发生了明显变化。

### 3.2 频域分析（1周）

**学习内容**：
- 傅里叶变换（FFT）的直觉理解：时域信号 ↔ 频域信号的转换
- 频谱图（Spectrum）如何解读
- 如何在频谱图上定位轴承特征频率（BPFO/BPFI等）及其谐波
- 边频带（Sideband）现象：齿轮/轴承故障常伴随的调制现象
- 功率谱密度（PSD, Power Spectral Density）

**动手项目**：
对CWRU数据集中不同故障类型（内圈/外圈/滚动体故障）的信号做FFT，观察频谱图上特征频率峰值的位置，验证是否与理论计算的BPFO/BPFI吻合。

### 3.3 时频分析（1周，处理非平稳信号的关键）

**为什么需要**：FFT假设信号是平稳的（统计特性不随时间变化），但实际工况下转速会变、负载会变，信号是非平稳的，此时需要时频分析。

**学习内容**：
- 短时傅里叶变换（STFT）：滑动窗口做FFT，得到时间-频率-能量的三维图（时频谱）
- 小波变换（Wavelet Transform）：比STFT更适合捕捉瞬态冲击信号，因为可以自适应调整时间/频率分辨率
- 包络分析（Envelope Analysis / Envelope Spectrum）：**轴承诊断中最经典、最实用的方法之一**，通过希尔伯特变换提取信号包络，再做FFT，专门用于放大周期性冲击信号的特征频率
- （可选进阶）经验模态分解（EMD）/变分模态分解（VMD）：把复杂信号分解成若干本征模态分量

**动手项目**：
对同一段轴承故障信号，分别做：原始频谱 vs 包络谱，对比哪种方法能更清晰地看到故障特征频率。这是业界诊断轴承故障最常用的实操对比。

### 推荐资源
- Python库：`scipy.signal`（FFT、滤波、包络）、`PyWavelets`（小波变换）
- 搜索："bearing envelope analysis tutorial python"
- B站/YouTube搜索"信号处理 傅里叶变换 直观理解"类科普视频先建立直觉，再看工程实现

### 自测标准
给你一段未知故障类型的轴承振动信号，你能独立完成：时域特征计算 → FFT频谱 → 包络谱分析 → 判断大致是内圈/外圈/滚动体哪种故障。

## 阶段四：机器学习方法在故障诊断中的应用（2-3周）

### 4.1 特征工程与降维（3-4天）

**学习内容**：
- 把阶段三的时域+频域+时频域特征组合成特征向量（Feature Vector）
- 特征选择方法：相关性分析、方差过滤、基于树模型的特征重要性
- 降维方法：PCA（主成分分析）、t-SNE/UMAP（用于可视化高维特征分布）

**动手项目**：
对CWRU数据集提取几十个特征后，用PCA降到2维，画散点图，看不同故障类型是否能自然分开。

### 4.2 无监督异常检测（1周）

**为什么重要**：实际工厂里，"正常"数据很多，但"故障"数据很少（设备大部分时间是健康的），这是典型的**类别不平衡**问题，很多时候甚至没有故障标签，这时需要无监督方法。

**学习内容**：
- 基于统计的方法：3-sigma原则、控制图（Control Chart）
- 孤立森林（Isolation Forest）：通过随机切分找出容易被孤立的异常点
- One-Class SVM：只用正常数据训练边界，边界外的判为异常
- 自编码器（Autoencoder）：用正常数据训练一个"压缩-重构"网络，故障数据因为模式不同会导致重构误差变大，异常检测本质是看重构误差

**动手项目**：
只用正常工况数据训练一个Autoencoder，然后在故障数据上测试重构误差是否明显升高，画出重构误差随时间变化的趋势图，模拟真实的"异常报警"场景。

### 4.3 有监督故障分类（1周）

**学习内容**：
- 传统机器学习分类器：随机森林、SVM、XGBoost（在中小数据集、特征工程做得好的情况下，往往比深度学习效果更好、更快、更好解释）
- 深度学习分类器：
  - 1D-CNN：直接在原始振动信号或频谱上做卷积，自动学特征
  - 2D-CNN：把信号转成时频图（如小波时频图）当图像输入，用图像分类的CNN架构
  - LSTM/GRU：适合处理时序依赖关系强的场景
- 模型评估：准确率、精确率/召回率、F1、混淆矩阵（在类别不平衡场景下，准确率会骗人，一定要看混淆矩阵）

**动手项目**：
在CWRU数据集上，分别用"手工特征+随机森林"和"1D-CNN原始信号"两种方案做故障分类（正常/内圈/外圈/滚动体故障），对比准确率、训练时间、可解释性的差异，形成自己的方法论判断。

### 推荐资源
- scikit-learn官方文档（随机森林、SVM、Isolation Forest都有现成示例）
- PyTorch或TensorFlow任选一个深入学，官方教程即可
- 论文可搜索："CNN bearing fault diagnosis"、"autoencoder anomaly detection vibration"

### 自测标准
拿到一份新的（你没见过的）轴承数据集，能独立完成：特征提取 → 训练一个分类器 → 输出准确率和混淆矩阵 → 判断模型是否可信（有没有过拟合、数据泄漏等问题）。

## 阶段五：剩余寿命预测 RUL（Remaining Useful Life）（2周）

这是预测性维护区别于"故障诊断"的核心部分——诊断解决"现在坏没坏"，RUL解决"还能撑多久"。

### 学习内容

1. **RUL的问题定义**：给定设备从健康到失效的历史退化数据，预测当前时刻设备的剩余寿命
2. **健康指标构建（Health Indicator, HI）**：如何把多维传感器数据融合成一条能单调反映退化趋势的曲线（这是RUL预测成败的关键前置步骤，比模型选择更重要）
3. **退化建模方法**：
   - 基于物理模型（Physics-based）：了解即可，需要领域专家的失效物理方程
   - 基于数据驱动（Data-driven）：这是我们要重点掌握的
4. **数据驱动RUL预测方法**：
   - 传统回归方法：把特征回归到剩余寿命数值
   - LSTM/GRU时序模型：输入历史传感器序列，输出RUL
   - CNN-LSTM混合模型：CNN提特征，LSTM建模时序演化趋势
   - （进阶）Transformer架构在RUL预测上的应用
5. **RUL预测的评估指标**：
   - RMSE（均方根误差）
   - Score函数（PHM08/NASA竞赛专用的非对称评分函数，预测过晚比预测过早惩罚更重，因为迟预测可能导致设备真的坏了）

### 动手项目

用NASA C-MAPSS涡扇发动机退化数据集（RUL预测领域的"MNIST"）完成：
1. 构建健康指标曲线
2. 训练一个LSTM模型预测RUL
3. 用官方Score函数评估模型
4. 对比"预测早了"和"预测晚了"对实际决策的影响，理解为什么这个领域格外重视预测的"保守性"

### 推荐资源
- NASA C-MAPSS数据集（NASA Prognostics Data Repository，免费公开）
- 论文搜索："RUL prediction LSTM C-MAPSS"，找几篇引用量高的论文看方法和思路（不需要复现所有细节，理解思路即可）

### 自测标准
能解释清楚：为什么RUL预测不能只看RMSE，还要看预测的时机（早/晚）分布。

## 阶段六：系统集成与工程化思维（1周）

算法之外，你需要理解自己的模型将来是怎么被用起来的，这样设计模型时才会考虑现实约束。

### 学习内容

1. **典型PHM系统架构**：
   传感器 → 边缘网关（初步滤波/特征提取）→ 时序数据库 → 模型推理服务 → 报警/看板/工单系统
2. **模型部署的现实考量**：
   - 推理延迟要求（是否需要实时报警）
   - 模型漂移（设备工况变化后模型是否需要重新训练）
   - 误报率控制（工厂对"狼来了"式的误报非常敏感，会导致运维人员不信任系统）
3. **相关标准（了解即可，加分项）**：
   - ISO 10816/20816：机械振动评价标准
   - ISO 13374：状态监测与诊断系统的数据处理框架

### 自测标准
能画出一张完整的架构图，说明你的模型在整个系统里处于什么位置，输入输出是什么。

## 多场景实战案例库（15个不重复场景，覆盖不同技术路线）

**为什么要看多个场景**：如果只用轴承数据练手，很容易把"FFT找峰值+CNN分类"当成万能模板，套到所有问题上。但实际工业场景的传感器类型、退化规律、诊断思路差异很大。这个案例库刻意挑选了技术路线完全不同的场景，建议你在学完对应阶段后，选1-2个场景动手做一遍，逼自己跳出单一思维模式。

| 9 | 半导体制造设备腔体漂移检测 | 精密制造 | 射频功率、压力、气体流量等上百个过程变量 | 高维多变量统计过程控制（PCA/T²/SPE） | 阶段四 |
| 10 | 电梯曳引机健康监测 | 特种设备 | 加速度计、编码器、电流 | 多源异构数据融合诊断 | 阶段四 |
| 11 | 光伏组件性能衰减检测 | 新能源发电 | I-V曲线、组件温度、辐照度 | 性能曲线偏差+天气归一化处理 | 阶段四 |
| 12 | 输油/输气管道泄漏检测 | 长距离管网 | 压力/流量瞬态波动、分布式声波传感 | 空间定位型诊断（负压波法，类似声源定位） | 阶段三 |
| 13 | 工业机器人关节减速器退化监测 | 智能制造 | 电机电流、编码器位置反馈 | 利用控制系统指令-反馈偏差做诊断，无需额外传感器 | 阶段四 |
| 14 | 中央空调冷水机组制冷效率衰退监测 | 暖通/楼宇 | 进出水温度、流量、压缩机功率 | 能量平衡模型+故障归因分类 | 阶段四 |
| 15 | 燃气轮机热通道部件寿命预测 | 航空/能源 | 排气温度分布、转速、燃气压力（无法直接测叶片） | 物理模型（蠕变寿命公式）+数据校正的混合建模 | 阶段五 |

### 建议的练习方式

不需要每个都做，但建议按下面的节奏挑着练，确保覆盖不同技术范式：

- **学完阶段三（信号处理）后**：挑 #5（电机MCSA）或 #8（铁路阶次分析），体会"同样是频域分析，不同物理机理下特征频率的产生原因完全不同"
- **学完阶段四（机器学习方法）后**：挑 #2（变压器DGA）或 #9（半导体多变量过程控制），体会"不是所有异常检测都靠信号波形，多变量统计方法是另一条完全不同的路线"
- **学完阶段五（RUL预测）后**：挑 #6（锂电池）或 #1（刀具磨损），体会"退化曲线的形状（单调 vs 两阶段拐点）直接决定了该用什么模型"
- **综合大项目阶段**：可以挑 #12（管道泄漏定位）或 #15（燃气轮机混合建模）作为进阶挑战，这两个的问题定义本身就和标准的"分类/回归"框架不一样，逼你重新思考问题该怎么建模

### 数据获取提示

这些场景中，#1（PHM 2010刀具磨损）、#6（NASA电池老化数据集）有现成的公开数据集可以直接练手；其余场景（如#2变压器DGA、#9半导体过程数据）公开数据集较少，建议的做法是：先搜索相关领域的学术论文，看别人是怎么定义特征和标签的，再用仿真数据或简化场景自己动手实现一遍算法逻辑（哪怕数据是自己模拟的，也能锻炼建模思路）。

## 最终自查清单（判断你是否真的学会了）

- [ ] 能独立对一段振动信号完成时域+频域+包络谱分析，并给出物理解释
- [ ] 能独立设计并训练一个异常检测模型，在没有故障标签的情况下发现异常
- [ ] 能独立设计并训练一个故障分类模型，并用混淆矩阵而不是准确率来评估
- [ ] 能独立构建健康指标曲线，并训练RUL预测模型
- [ ] 能向一个不懂算法的工厂工程师，用通俗语言解释你的模型为什么可信
- [ ] 能画出完整的系统架构图，说明数据从传感器到报警的全链路
- [ ] 拿到一个新场景（哪怕是案例库里没细讲的），能先判断"这个问题的退化规律是什么类型（周期冲击/渐进磨耗/两阶段拐点/宽带噪声/多变量漂移等）"，再决定该用哪类方法，而不是无脑套用FFT+CNN模板
